## Why this matters

Every closure call matches arguments in `match_closure_args`. Builtins and `match.call` go through a second port, `matchArgs_NR_local`. Both claim to follow GNU `match.c` and the R Language Definition: exact names, then partial names, then positional. They do not share code. Tests cover a handful of happy paths, not the partial-match cases that make R matching surprising.

Kani should prove one pure specification. The production SEXP functions stay in place until that specification and both ports agree on a fixed oracle. Replacing either port in this plan would risk a language-behavior change in order to make a proof easier.

This is the first semantic proof. It is independent of the bytecode VM. Do not block it on `bcEval`.


Builtin matcher, `crates/rmath/src/mainutils/match_mod.rs:528`. The comment immediately above `matchArgs_NR_local` says it is the production three-pass matcher and that closure evaluation uses `eval/closure.rs::match_closure_args`, a second port of the same GNU `match.c` algorithm. The function signature is:

```rust
pub(crate) unsafe fn matchArgs_NR_local(formals: SEXP, supplied: SEXP, call: SEXP) -> SEXP
```

`match_closure_args` returns `Result`. `matchArgs_NR_local` raises `panic_any(RError)`. Partial matching in the closure port uses Rust `starts_with`. The builtin port uses `pmatch` / encoding helpers. Those differences are why the pure spec must not be generated by copying one body.

Language rules to encode, from `r-source/doc/manual/R-lang.texi` section "Argument matching" (around the exact / partial / positional description) and `r-source/src/main/match.c` `matchArgs_NR`:

- Exact tag match first. One actual must not exactly match two formals, and one formal must not take two exact actuals.
- Partial match is a non-empty prefix of the formal name, only among formals before the first `...`, only for actuals not already used, and only if exactly one remaining formal matches. Zero partials is fine. Two or more is an error even when each formal would have had a unique actual (`fumble` / `fooey` with tags `f` and `fo`).
- An exact match removes that actual from the partial pool (`f` plus `fooey` can both succeed).
- Positional matching fills only still-unmatched formals before `...`, using only untagged unused actuals, in order.
- Formals after `...` are exact-only. They do not take partial or positional actuals.
- Leftover actuals become `...` in supplied order when `...` exists. Otherwise they are an unused-argument error.
- Unmatched non-dot formals are missing. Do not model default promises.

The single integration test to keep green is `match_closure_args_follows_gnu_three_pass` in `crates/rmath/src/eval/eval.rs` (the four-case exact / positional / reorder / partial test). Per-builtin helpers named `match_args` in `crates/rmath/src/mainutils/qr_*.rs` are local parsers. Do not touch them.

## Steps

### Step 1: Write the pure spec from the language rules, not from either port

`argmatch.rs` contains:

```rust
pub(crate) struct Formal {
    pub name: Option<String>, // None only for the dots formal; dots also sets is_dots
    pub is_dots: bool,
}
pub(crate) struct Supplied {
    pub tag: Option<String>,
}
pub(crate) enum Binding {
    Missing,
    Actual(u8),
    Dots(Vec<u8>),
}
pub(crate) enum MatchError {
    MultipleExact,
    MultiplePartial,
    Unused,
}
pub(crate) fn match_formals(formals: &[Formal], supplied: &[Supplied]) -> Result<Vec<Binding>, MatchError>
```

Indexes in `Actual` / `Dots` refer to `supplied`. Implement the eight rules in Current state. Empty supplied tag (`Some("")`) is a partial prefix of every name; with two candidate formals that is `MultiplePartial`. An absent tag (`None`) is positional, not partial.

No SEXP, no `unsafe`, no panic on well-formed input. Invalid shapes (two `...` formals) return `MatchError` or are excluded with a documented precondition check that returns `Err`. Pick one and test it. Do not panic.

**Verify**: `scripts/cargo_dev.sh test -p rmath --lib argmatch::` compiles. Tests come in step 3; a single smoke test is enough here if you want a checkpoint.

### Step 2: Kani the spec inside a small bound

Harness `argmatch_spec`. Bounds: at most 3 formals, at most 3 supplied arguments. Names are drawn from `["", "a", "ab", "b", "f", "fo", "foo"]` by symbolic index, or `None`.

Assert, for every input in that box:

- On `Ok`, every supplied index appears in at most one `Actual` or `Dots` entry.
- On `Ok`, every `Actual(i)` index is `< supplied.len()`, and dots indexes are unique and in range.
- A supplied tag that equals a formal name before `...` is bound to that formal whenever the result is `Ok` (exact wins over a later partial or positional use).
- No `Ok` result binds a partial or positional actual to a formal that occurs after `...`.
- If any formal `is_dots`, leftover tagged and untagged actuals are in `Dots` in increasing supplied index order.
- If no formal `is_dots` and some supplied index is unbound, the result is `Err(Unused)` or another error, never `Ok`.
- `kani::cover`: exact-only success, the `f`/`fo` double partial error, a dots collection, a positional fill, and an unused-argument error.

Do not call `match_closure_args` from Kani.

**Verify**: `scripts/cargo_kani.sh -p rmath --no-default-features --harness argmatch_spec` → `VERIFICATION:- SUCCESSFUL`.

### Step 3: Oracle table, then differential tests against both ports

Encode these cases as data in the unit test, each with the `match_formals` expectation. Names are ASCII.

| Case | Formals | Supplied tags | Expect |
| --- | --- | --- | --- |
| Exact and reorder | `a, b` | `b=1, a=2` | actuals `[1, 0]` |
| Positional | `a, b` | untagged, untagged | actuals `[0, 1]` |
| Partial unique | `foo, bar` | `f` | `foo` gets 0 |
| Double partial | `fumble, fooey` | `f`, `fo` | `MultiplePartial` |
| Exact removes partial candidate | `f, fooey` | `f`, `fooey` | both exact, `Ok` |
| Partial before dots only | `a, ..., b` | `bb` | `Unused` (must not bind `b`) |
| Exact after dots | `a, ..., b` | `b=1` | `b` gets that actual |
| Positional stops at dots | `a, ..., b` | untagged | `a` gets it, `b` missing |
| Dots keep order | `...` | untagged, `z`, untagged | dots indexes `[0, 1, 2]` |
| Unused | `a` | `b=1` | `Unused` |
| Missing formal | `a, b` | one untagged | second formal `Missing` |

For each `Ok` case and each error case that both ports can represent, build the same formals and supplied pairlists and call `match_closure_args` and `matchArgs_NR_local`. Compare the slot assignment (which supplied CAR landed on which formal, and which formals are missing), not the error string.

If the two ports disagree with each other or with `match_formals`, STOP. Record the case, both results, and the R Language Definition rule you used. Do not edit either port to force agreement.

`matchArgs_NR_local` panics on unused arguments. Catch that with `catch_unwind` in the unit test only, and treat an `RError` panic as the error result. A panic that is not `RError` is a test failure.

**Verify**: `scripts/cargo_dev.sh test -p rmath --lib argmatch_oracle` → exit 0, and the output includes the eleven cases (test names or a single test with eleven assertions). `match_closure_args_follows_gnu_three_pass` still passes.
